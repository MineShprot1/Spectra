## Получить .exe без Visual Studio

1. Распакуйте архив. Содержимое папки `Spectra` загрузите в корень своего репозитория `MineShprot1/Spectra`, включая `.github`.
2. На GitHub откройте **Actions → Build Spectra for Windows → Run workflow**. Workflow также запускается при push в `main`.
3. После успешного выполнения скачайте артефакт **Spectra-windows-x64**, распакуйте его целиком и запустите `Spectra.exe`.
4. Нужен **Microsoft Edge WebView2 Runtime**. Он обычно есть на актуальной Windows; если отсутствует, установите его с официального сайта Microsoft.

Workflow собирает .NET вместе с программой: пользователю готовой сборки не нужно ставить .NET отдельно. Папка `Web` должна лежать рядом с `.exe`. Автопубликация релизов и загрузка файлов в ваш GitHub не выполнялись.

## Сборка на своём компьютере

Установите **.NET SDK 8 x64**, откройте PowerShell в папке проекта и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\Build.ps1
```

Результат: `dist\Spectra\Spectra.exe`. IDE не обязательна. Для отладки:

```powershell
dotnet run --project src/Spectra/Spectra.csproj
```

## Первый вход и API

Стартовое компактное окно показывает статус обновлений: проверка пока отключена, как в задании. Затем предлагается вход Microsoft. Для просмотра библиотеки есть отдельная кнопка без входа; **игра без лицензионного аккаунта не запускается**.

При пустом `clientId` в `microsoft-oauth.json` используется **встроенный Windows OAuth2-провайдер CmlLib**. Нажмите «Войти с Microsoft»: библиотека показывает официальную страницу Microsoft в отдельном WebView2-окне. Собственное приложение и ручной ввод Client ID для этого режима не требуются. Это документированный провайдер библиотеки с конфигурацией Minecraft Launcher, а не авторизация вообще без OAuth-клиента. Его работоспособность, доступность для стороннего лаунчера и доступ Minecraft Services здесь не проверены и не гарантируются. Подмена OAuth2 на вход паролем или извлечение сессии другого лаунчера не используются.

Если разработчик вписал собственный действительный `clientId`, используется сохранённый MSAL-вход через браузер по умолчанию и callback `http://localhost`. Для этого варианта нужна соответствующая регистрация Microsoft и доступ Minecraft Services. Кэш MSAL (`msal-browser.dat`) защищён Windows DPAPI. Ошибка браузерного режима не вызывает скрытого переключения на другой OAuth-клиент. Ожидание ограничено пятью минутами.

Текущий архив по умолчанию использует встроенный провайдер. Выход очищает сохранённые сессии Spectra, но не cookies Microsoft во встроенном окне или внешнем браузере.

В текущей версии CurseForge и Crafty.gg используют встроенные ключи; пользователю не нужно вводить их в настройках. Modrinth работает без ключа на этих публичных операциях. Если источник недоступен, интерфейс сообщает об этом; результат другого источника остаётся доступен. Запрет автора на сторонние скачивания CurseForge не обходится: установка выдаёт понятную ошибку.

Сессии Microsoft и токены Crafty/CurseForge хранятся с Windows DPAPI для текущего пользователя. Access token Minecraft не передаётся HTML-интерфейсу. Новый файл сессий — `microsoft-accounts.dat`; вход по старому `account.dat` не восстанавливается, потребуется войти повторно. Для перехода между провайдерами может потребоваться повторный вход. Активен последний успешно сохранённый аккаунт; интерфейс отдельного выбора сохранённых аккаунтов пока отсутствует. Выход очищает сохранённые сессии лаунчера.

## Что ещё требуется перед готовым релизом

- **Проверить Windows build и все сетевые сценарии** с собственными ключами и лицензионным аккаунтом. Особенно старые Alpha/Beta, современные версии 26.x, загрузчики и разные модпаки: поддержку библиотеки нельзя считать проверкой каждой версии.
- **Точный GPU для каждого режима:** сейчас показывается список адаптеров, а режим записывается в Windows. Определение конкретного адаптера по DXGI GPU preference ещё не реализовано. Windows может переопределить предпочтение; оно также общее для сборок, использующих один и тот же Java executable.
- **Профиль Crafty:** добавлены блоки информации, истории ников и истории скинов. Доступ к Crafty требует API-токен. Поля истории зависят от ответа сервиса; их полнота не гарантируется. Смена игрового профиля подключена к Minecraft Services; для неё действуют серверные ограничения. Аватар вырезается из текстуры скина; при недоступной текстуре остаются инициалы.
- **Полные метаданные локальных дополнений:** Forge/NeoForge TOML, shader/resource pack описания, поддерживаемые версии и иконки всех форматов ещё не разбираются; имя файла остаётся резервным отображением.
- **Редактор компонентов** сейчас показывает реальные компоненты и меняет версию. Произвольные операции с LWJGL/JAR/Java agents и перестановка компонентов со скриншота не реализованы.
- **Steam-подобная витрина:** есть выделенная карточка и карточки каталога, но нет карусели редакционных подборок и страниц подробностей проекта.
- **Загрузка:** нет кнопки отмены, очереди с восстановлением, лимита скорости и транзакционного отката установки отдельных дополнений в существующую сборку. Modrinth optional dependencies пока не предлагаются отдельно. При проблеме модпака с запрещёнными файлами CurseForge требуется ручная установка.
- **Оптимизация:** сетевые операции асинхронные, изображения lazy, список версий порционный, лог ограничен. Добавлены кэш метаданных версий, кэш текстур до 64 записей, content-visibility списков и ограничение частоты байтового прогресса. 3D-превью не использует постоянный цикл рендеринга. Полноценные измерения CPU/RAM/времени запуска пока не проведены; постоянный офлайн-кэш каталогов и общие игровые assets ещё не сделаны.
- **Серверы:** Vanilla не записывает историю последнего посещения в `servers.dat`; показывать выдуманную дату нельзя. Редактирование серверов и отслеживание посещений ещё не добавлены.
- **Обновления:** проверка/установка релизов GitHub, подпись `.exe`, инсталлятор и восстановление после повреждённого config ещё впереди.

В текущей среде выполнены:

- `node --check src/Spectra/Web/app.js` — прошёл;

**Не выполнены здесь:** `dotnet build`, C# тесты, UI smoke в Chromium, вход Microsoft, установки и реальная игра. Workflow включает эти локально доступные проверки: C# build, девять core проверок (пути, память, сериализация, NBT), UI smoke (навигация, фильтры, создание, вкладки, настройки, компактный размер) и публикацию Windows x64. ## Изменения 0.3

- Быстрый запуск слева снизу: выбранная версия или сборка/модпак, список выбора и кнопка «Играть». Выбор и виды списков сохраняются в config.
- Выбор версии больше не создаёт сборку. Vanilla запускается в отдельной постоянной `.minecraft` (`instances/vanilla`), отсутствует в списке сборок и использует общие настройки. Все выбранные vanilla-версии используют эту папку; для отдельных миров и модов создавайте сборки.
- Карточки / крупные плитки / компактный список отдельно для версий и сборок.
- Байты загружено/всего: для Java, модов и модпаков — текущий файл; CmlLib — обработанные файлы текущего этапа, включая проверенные ранее скачанные файлы. Это не общий размер всего модпака. При отсутствии Content-Length размер помечается неизвестным. Завершение/ошибка очищают индикатор.
- Своя локальная коллекция PNG скинов: добавить, посмотреть модель, надеть через Minecraft Services, удалить из коллекции. Скины видны только в профиле совпадающего UUID в интерфейсе (это не шифрование PNG на диске). Прямое «Загрузить и надеть PNG» не добавляет файл в коллекцию; используйте «Добавить PNG» для сохранения.
- 3D-превью с мышью и стрелками, классические/тонкие руки, второй слой. Старый 64×32 формат использует те же UV для парных конечностей; точное зеркалирование старых конечностей пока не выполнено. Плащ на 3D-модели не отображается.
- UUID, модель, ссылка Crafty, статус, дата профиля Crafty, история имён/скинов при наличии полей в API. Дата создания Minecraft-аккаунта не выдаётся за дату Crafty; при отсутствии источника показывается «Не предоставлена». Полную историю всех имён/скинов обещать нельзя: источник может не знать или скрывать записи. Живое соответствие схемы Crafty не проверялось без токена.
- Текстуры текущего Minecraft-скина получаются через C# с ограничением 1 МБ; локальные текстуры обслуживаются отдельным виртуальным skin-хостом для Canvas.

В этой среде не было .NET SDK/Windows и браузера Chromium: новый C# и 3D-визуализация не были запущены. Проверены синтаксис JavaScript, логика выбора без создания сборки, форматирование байтов и существующие логические проверки. UI smoke обновлён под новый сценарий, но здесь не выполнен.

- Общие состояния кнопок запуска: «Играть», «Подготовка…», «Остановить». Панель синхронизируется с событиями начала/выхода процесса. Добавлены короткие анимации панели/нажатия с учётом reduced-motion.
- Windows 11: запрос нативного скругления через DwmSetWindowAttribute (DWMWA_WINDOW_CORNER_PREFERENCE); Windows определяет итоговое оформление. При разворачивании предпочтение переключается на квадратное окно, на Windows 10 запрос не выполняется. Это поддержка скругления, а не заявление о соответствии всем требованиям Windows 11.

### Личный файл API-ключей

Переданный пользователем файл `api-keys.local.json` предоставляется отдельно и не включён в публичные исходники. Положите его рядом с `Spectra.exe` перед запуском. При локальной сборке можно положить его рядом с Build.ps1: скрипт скопирует файл в dist/Spectra. Git игнорирует файл. Действительность ключей и живые API здесь не проверялись.

## Импорт и экспорт Prism / MultiMC (0.4)

В «Сборках» появилась кнопка **Prism / MultiMC ZIP**. Также можно перетащить один ZIP-файл в окно Spectra; файл передаётся C# через AdditionalObjects WebView2, без чтения всего архива в JavaScript. Для drag-and-drop нужен актуальный WebView2 Runtime. Обычный браузерный preview не импортирует файлы.

Импорт распознаёт `instance.cfg`, `mmc-pack.json` в корне или единственной вложенной папке и игровые файлы в `.minecraft/` или `minecraft/`. Сохраняет название, известный загрузчик и его версию, override памяти, локальную PNG-иконку и игровые файлы. Не импортирует путь Java, произвольные JVM-аргументы и команды до/после запуска; Java выбирается настройками Spectra. Поддержаны Vanilla, Fabric, Forge, Quilt, NeoForge. Сборки с неизвестными компонентами или пользовательскими `patches` отклоняются с объяснением. Не поддержаны устаревшие экспорты без mmc-pack.json. Для проверки версии требуется соединение с Mojang.

Кнопка со стрелкой загрузки в строке сборки открывает экспорт. Выберите целевой лаунчер и включение миров/скриншотов, затем сохраните ZIP. Экспорт записывает `instance.cfg`, `mmc-pack.json`, `.minecraft`, моды, конфиги, ресурс-паки, шейдеры и другие пользовательские игровые файлы. Локальная PNG-иконка переносится; удалённая URL-иконка и баннер не экспортируются. Миров и скриншотов по умолчанию в ZIP нет. Также исключены библиотеки, assets, версии Minecraft, natives, логи, crash reports и известные файлы аккаунтов. Произвольные личные файлы в игровых папках могут попасть в архив — перед распространением проверьте содержимое.

Prism поддерживает весь перечисленный набор загрузчиков; для Quilt/NeoForge экспорт в MultiMC блокируется. Vanilla/Fabric/Forge используют общий формат. Получающий лаунчер скачивает Minecraft/загрузчик по собственным метаданным: доступность очень новых или старых версий зависит от него. Реальный импорт полученного ZIP в Prism/MultiMC здесь не тестировался.

Импорт проверяет выход путей, повторяющиеся имена, ссылки, количество файлов (50 000), метаданные (1 МиБ) и суммарный заявленный распакованный размер (8 ГиБ). Установка выполняется в новую папку, неудачная попытка удаляется. Экспорт нельзя начать при запущенной игре, создаётся во временном файле и заменяет выбранный ZIP только по завершении. C#-сборка здесь не выполнена; проверки JavaScript/XML прошли.

## Переработка отрисовки 0.4.1

У списков и панелей отключено живое backdrop-размытие; стеклянное оформление сохраняется статическими прозрачными заливками, границами и бликами. Убрана анимация целого контейнера страницы и постоянное движение декоративных блоков. Размытые изображения карточек теперь один раз растеризуются в Canvas 256×128 вместо CSS-фильтра при каждой композиции кадра. Аппаратное ускорение WebView2 не отключается приложением; ошибки драйвера или программный рендеринг требуют отдельной диагностики на компьютере пользователя.

## Профиль и обновления 0.4.2

История скинов Crafty отображает парные виды спереди/сзади и кнопку 3D-превью. Для этого источник должен предоставлять URL текстуры; при отсутствии URL показывается объяснение. Картинки готовятся при приближении к видимой области, чтобы длинная история не загружалась целиком сразу.

Каждый доступный плащ получает 2D-превью внешней/внутренней стороны. Активный плащ (`state=ACTIVE`) прикрепляется объёмным элементом к спине 3D-модели. После смены/скрытия плаща профиль заново запрашивается у Minecraft Services, и модель перестраивается. Поддержаны текстуры плащей 64×32, 128×64, 256×128. Плащ статичен: игровая физика движения и элитры не моделируются. Для чужого игрока текущий плащ берётся из Mojang sessionserver; исторические плащи не восстанавливаются.

При запуске выполняется запрос `https://api.github.com/repos/MineShprot1/Spectra/releases/latest` с тайм-аутом 8 секунд. Сравниваются числовые версии тегов `v0.4.3`, `0.4.3`, `Spectra-0.4.3`; draft/prerelease пропускаются. На стартовом экране и в нижней панели появляется кнопка открытия страницы нового релиза. Это проверка и переход к скачиванию, не автоматическая замена файлов приложения. Для неё нужно публиковать GitHub Releases: одних push, тегов или Actions artifacts недостаточно. Нет релиза/сеть недоступна — вход и запуск продолжаются. Репозиторий и наличие его релизов из этой среды подтвердить не удалось.

JS-тесты превью плаща прошли; C#-тесты разбора версий добавлены в Windows workflow, здесь не выполнены. Визуальная проверка на Windows, вход и живые данные Crafty/Minecraft по-прежнему не проверены.

## Обновление по коммитам (0.5)

Вместо Releases приложение проверяет последний коммит **ветки по умолчанию** `MineShprot1/Spectra`. SHA установленной сборки хранится в `build-commit.txt`: GitHub Actions и Build.ps1 (если доступен Git) проставляют его при сборке. Если маркера нет, первая проверка считает версию исходников неизвестной и предлагает/запускает полное первичное получение репозитория.

Новый коммит автоматически запускает подготовку обновления на стартовом экране. **Нужен .NET SDK 8 x64** и доступ к NuGet/GitHub; одного runtime недостаточно. Последовательность: снимок дерева точного SHA → проверка локальных файлов по Git blob SHA-1 → скачивание только новых/изменённых файлов → новая папка исходников без удалённых файлов → dotnet publish → отдельный помощник PowerShell → завершение Spectra → замена изменившихся файлов приложения → перезапуск. При первом обновлении кэш пуст: скачиваются все исходники. При последующих неизменённые файлы копируются из `%LOCALAPPDATA%/Spectra/updates/source`. Отдельно .NET может скачивать отсутствующие NuGet-пакеты.

Исходники нельзя просто скопировать поверх C# executable, поэтому программа обязательно компилируется локально. Сравнение файлов опубликованного приложения по SHA-256 позволяет не заменять совпадающие бинарники и веб-файлы. Удалённые исходники отсутствуют в новом снимке; удалённые файлы программы убираются только по предыдущему `installed-files.json` (при первом переходе неизвестные старые файлы не удаляются). Настройки OAuth текущей установки сохраняются. `%LOCALAPPDATA%/Spectra/instances`, аккаунты и настройки не входят в замену. Обновление при запущенном Minecraft блокируется.

Если скачивание/компиляция не удалась, текущая программа продолжает работать. Коммит записывается в `updates/failed-commit.txt`: автоматическая повторная попытка для него блокируется, кнопку ручной попытки можно нажать снова. Build-лог: `updates/last-build.log`. На этапе применения создаётся резервная копия изменяемых файлов в `updates/jobs/<id>/backup`; помощник пытается восстановить её при ошибке и сохраняет `apply-error.txt`. Откат — попытка восстановления файлов, не гарантия при потере питания или повреждении диска. Успешный запуск нового exe не проверяется на дальнейшие runtime-ошибки. Резервные копии оставлены для ручного восстановления.

Репозиторий должен содержать `src/Spectra/Spectra.csproj` прямо от своего корня. Исходники ограничены 10 000 файлов, 32 МиБ на файл, 256 МиБ всего; символические ссылки и неполные ответы дерева отклоняются. Скачивание привязано к конкретному коммиту и проверяется Git-хешем. Компиляция выполняет MSBuild проекта из вашего репозитория. Процесс публикации ограничен 15 минутами. Полный runtime-сценарий, сборка C# и PowerShell-помощник здесь не запущены: .NET SDK/Windows в этой среде отсутствовали.
