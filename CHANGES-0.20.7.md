# Spectra 0.20.7

В группе → «Настройки соединения» добавлены кнопки «Разрешить P2P в брандмауэре» и «Удалить правила».

Windows запрашивает повышение прав только для отдельной команды настройки. Сам лаунчер остаётся без административных прав. Определяется путь настоящего браузерного процесса текущего WebView2 через BrowserProcessId; интерфейс не может передать произвольный путь программы, порты или команды.

Создаются два именованных разрешающих UDP-правила (входящее и исходящее) для конкретного файла msedgewebview2.exe, профилей Private и Public. Порты WebRTC динамические, поэтому разрешение ограничено программой, а не одним портом Minecraft. Правила действуют и для других приложений с тем же файлом WebView2; это указано в интерфейсе. Системный брандмауэр не отключается, другие правила не удаляются, правила Domain не создаются. Кнопка удаления удаляет только два правила Spectra Party. Повторное применение заменяет их, обновляя путь WebView2, и не создаёт дубликаты.

После успешной настройки повторите подключение. После обновления WebView2 путь файла может измениться — тогда примените правила снова. Если запрос UAC отменён, настройка не запускается. При ошибке команды отображается сообщение и кнопки снова доступны.

Это не открывает порт на роутере, не отменяет ограничения провайдера/NAT и не гарантирует прямое соединение. При явном запрещающем правиле или корпоративной политике разрешающего правила может оказаться недостаточно.

Проверены компиляция Windows-хелперов с Windows Desktop references, синтаксис C#12, тесты формирования правил/безопасного экранирования путей/удаления, npm test, npm run test:dom (разрешение, удаление, ожидание, отмена UAC и ошибка). Реальное создание правил и UAC на Windows, полная WPF-сборка и подключение двух удалённых компьютеров здесь не проверялись. Сервер и установщик не изменены.
